# Kuna fork acceptance on Aster

The local branch `lain/kuna-completion` continues Gemini Neon's fork from
`5973ace5b6e8`. The three inherited commits are `4aedeb161bf1` for function
boundaries, `01ef722b9c1b` for address-keyed exports and `bf4e20a6a3e9` for
PDB ingestion. The MSVC class-recovery changes arrived as a working-tree patch
and two new Rust modules. Their contents matched the source checkout at transfer.

| Blueprint | Evidence |
|---|---|
| Function boundaries | A native CLI process accepted 300,000 synthetic declarations from a 7,200,014-byte file. With two workers and two selected addresses it returned the two requested names. This case measures declaration transport and selection. On the PE64 metadata fixture, `pdataonly` returned the three expected extents of 16, 64 and 8 bytes. |
| Address-keyed exports | The CLI writes `src/rva_XXXXXXXX.c` slabs or individual `funcs/0xXXXXXXXX/0xYYYYYYYY.c` files. Every address-keyed layout publishes a final index. Rows identify the RVA bucket and, for C files, the exact path and byte span. The database reader supports unsigned 64-bit ranges and literal underscores in symbol names. |
| PDB ingestion | A matching PDB restored `pdb_demo_compute` on the freestanding PE. A mismatched PDB left it unnamed. The supplied MSVC fixture passed checks for types, prototypes, locals and inline ranges. The small checked-in CodeView case exercises two callers in a regular test run. |
| MSVC classes | On the supplied PE with the sidecar absent, `Actor::Actor`, `Entity::Entity` and `Actor::~Actor` matched the addresses from the PDB. Serial and two-worker streaming exports agreed on all 29 named struct definitions in the sampled header. |
| Outlining | A caller-selected region that writes the stack pointer stays inline. Prototype prerequisites are checked before changing the graph, and a declared return value that survives along a continuation path counts as an output. Compiler-attributed inline ranges are available through the function inventory. Unattended stripped-binary region detection, synthesized helper bodies and the deduplicated helper library are outstanding. |

The manual outlining pass still processes the first supplied region for a
function. It requires one external edge entering the region, accepts at most
one live output, and declines internal calls and stores. General pre-SSA liveness remains open.

With generic structure inference enabled, two of three sampled method bodies
from the MSVC fixture were byte-identical between the serial and two-worker
streaming exports. The serial export inferred an anonymous parameter struct
for `Actor::serialize`. With `protoorder` and `structsynth` both off, all three
bodies and the header matched. The worker regression checks the named class and
vftable layouts directly.

The PDB and DWARF fixtures use the same small C++ source. Two builds in
separate directories produced identical PE, PDB and ELF bytes. The fixture
directory contains the source, the build commands and the optional larger
MSVC reference source. DWARF inline names and origin references are currently
resolved within a compilation unit.

## Compatibility cases

Gemini Neon's saved executable and the initial local build emitted identical
C for `tree_range_members.c`. With `stackviews off`, an aligned member address
was cast to `Node **` when assigned to a local declared as `Node *`. The
correction uses the declared pointer type for that assignment. The regression
compiles and executes the generated program with GCC and Clang at `-O0` and
`-O2`, with incompatible pointer assignments treated as errors. The C from the corrected CLI also passed
all four compiler and optimization combinations with undefined-behavior
sanitization enabled.

The named and unnamed PDB procedure fixtures contain the same instructions.
A module-local symbol admits the named function. In the unnamed variant, the
only discovered interior entry remains available. The original fixture pair
regenerated byte-for-byte. The native test of the WASM front end also checks
fast project export both with and without a matching PDB.

## Checkpoint

The local build passed all 675 upstream data assertions and all 5,349 stage
assertions. The stage baseline gained the two stack-region assertions and
retained every previous passing case. The option catalog and spec checks
passed.

The final CLI verified two named functions in each of 15 combinations across
five layouts and three execution modes. Each indexed byte span identified its
function body. Database exports remained queryable after copying the finished
database file alone to a new directory and opening it in another CLI process.

The final `make rust-test` run passed 11,654 tests. Its default run marked
41 tests ignored. The supplied MSVC reference and storage benchmark
also passed when invoked explicitly. Aster used Rust 1.100.0, two visible
cores, one Cargo build job and the matching Debian Clang 19 sanitizer runtime
in the project-local test tools. The runnable CLI and its companions are under
`decompiler/target/lain-bin/` in this checkout. Their catalog and PDB readback
were checked with the working directory outside the checkout.

### Storage profile

The fork's storage benchmark completed with 300,000 synthetic function bodies
per layout on Aster. The native CLI matrix above covers the complete exports.

| Backend | Write time in seconds | Allocated MiB | Inodes | Median lookup in µs |
|---|---:|---:|---:|---:|
| Single C file | 0.20 | 118.9 | 3 | 1.7 |
| RVA slabs | 0.25 | 68.9 | 1,175 | 19.9 |
| One file per function | 9.31 | 1,172.1 | 301,175 | 10.4 |
| Turso | 17.80 | 100.4 | 3 | 49.8 |

The single-file measurement includes the JSONL index and uses a resident offset
table for lookup. The slab, per-function and Turso measurements cover their
backend files before the CLI adds its JSONL index. File timings include
buffered writes. These sizes and times apply to the measured artifacts.
